# Record: the console as a full peer, live (BS-03, 2026-10-16)

BS-03 asks for Link's [TEST-PLAN.md](https://github.com/Ableton/link/blob/master/TEST-PLAN.md) cases TEMPO-1 to
TEMPO-5 and STARTSTOPSTATE-2, with the plugin in peer mode (`BeatSync.Mode` `peer`, `BeatSync.Interfaces`
`127.0.0.1`). They ran on grandMA3 onPC 2.5.1 (macOS), on the disposable show `NewShow_2026.10.15_23.16.24UTC`, with
the plugin from branch bs-03-peer-probe imported at Plugin 2 and the console lock held. The other app was
`gbs-test-peer` (BS-04, the Link library) on the same computer. Speed master 12 was the tempo target. Afterwards
Plugin 2 was deleted, the `BeatSync.*` variables were deleted, and the master was back at 60 BPM with scale One. No
show was loaded or saved.

Scripts: `test/live/plugin_live.mjs peer-tempo --sequence 0` and `peer-startstop --sequence 0` (no chase is needed).
Raw output: [bs-03-live/](bs-03-live/).

## A run with another Link app on the network (invalid)

The first `peer-tempo` run failed 10 of 12 checks ([output](bs-03-live/peer-tempo-with-linkmaster-invalid.json)).
LinkMaster, a relay app, was still running on the computer, and it held a 120 BPM session:

- the console saw one peer before any test peer started;
- it joined the 120 BPM session (ahead of its own, `link/Sessions.hpp`);
- every tempo change, from the console or from the test peer, went back to 120 BPM.

This was the peer mode working as designed: a full peer changes everyone's session, and a relay that imposes its
tempo undoes the changes. It is why the peer scenarios need a network without other Link apps. After LinkMaster
was quit, every run passed.

  the plugin's loop (BS-02 record). The plugin is then started again, and starting into an existing session is
  what TEMPO-2 checks: the second half of TEMPO-2 is that case, with the console's old session kept by the test
  peer.

### The clock of a peer that measures the console

The BS-03 probe measured the error that a joining peer gets from the console's measurement replies, using a probe
chunk. This run measured it for the plugin itself, three times per `peer-tempo` run. The test peer joins the
console's session and measures the console's clock through the plugin's replies. An independent observer then
measures the test peer's clock, and the result is compared with the console's own clock, which is exact by
construction:

| Run | Error of the test peer's clock (ms) |
| --- | --- |
| 1 | −0.035, −0.031, −0.029 |
| 2 | −0.043, −0.040, −0.035 |
| 3 | −0.056, −0.053, −0.047 |

All 52 pings of each measurement were answered. The error includes the observer's own measurement error, and it is
far inside the 3 ms of Link's AUDIOENGINE-1 case.

**A precision fix.** The bridge returns Lua numbers to about 14 significant digits, so a microsecond time near
1.8 × 10^15 lost its last two digits. The first two clock comparisons came out at exactly 0.000 ms for that reason.
The observer now returns its intercept as text. The BS-02 records' beat offsets were computed from the rounded
intercept: each offset there may be off by up to 0.05 ms, which changes none of their conclusions.

## Changes found by the live run

- **STARTSTOPSTATE-2.** When the console joins a different session in peer mode, it resets its start/stop state,
  as `link/Controller.hpp` (joinSession) does. `link/Peers.hpp` passes on only a start/stop state that no member
  had before, so the members' existing state is not taken over. The follower (`Mode` `follow`) still reports the
  session's state as it is, since it is not a Link app.
- **The observer skips the console.** In peer mode the console announces itself. The observer must measure the
  test peer, not the console: the console answers once per frame, which misses the observer's 3 ms receives.

## Not covered

- Other computers and real network jitter: every peer ran on one computer, over the loopback.
- Ableton Live in the console's session. Live's session reaches this computer only through LinkMaster, which put
  every tempo change back to its own in the invalid run.
- Link's re-measurement every 30 s, and sessions longer than a few seconds.
